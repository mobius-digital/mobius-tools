Locus brand-first rebuild

Today a brand in Locus is its Meta ad account. After this, a brand is its own thing, and Meta, Triple Whale, Google, TikTok, Klaviyo, Asana and the rest are connections added on top of it.

Why

What broke, and why it will keep breaking

  • Ahsan tagged @Mobius Digital in #speedin-internal and got nothing. Speedin has no Meta account shared yet, so it can't exist in Locus, so the Slack router never treats the channel as a Locus channel.
  • New clients already hit this. The New client flow gives them a temporary asana_… ID, and some special code moves their data across when Meta arrives. Only 4 tables get moved, and everything else is stuck waiting.
  • Brands with more than one ad account (Party Patch has 2, Instant IV 3, Gum of Gods 2) show up as separate "brands".
  • Lineup and Pulse are moving into Locus next. They need one brand list to read from, and it can't depend on Meta.
The model

Brand first, connections on top

brand  (brand_speedin, permanent, never an outside ID)
 ├─ name, status, timezone, currency, goals, targets, team
 ├─ Slack: internal channel, brief channel, report channels
 └─ connections  (zero or more of each kind)
     ├─ meta       act_1352962423584020   connected · synced 2m ago
     ├─ meta       act_7012…              connected   ← a 2nd ad account
     ├─ triple whale  speedin.myshopify.com  not connected
     ├─ google / ga4 / gsc / tiktok / klaviyo / attentive
     ├─ asana project · drive · frame · atria
     └─ each one: status, last sync, last error
  • Brand-owned things (briefs, reports, goals, plan, season, angles, research, voice, Studio, assets, test library, costs) are filed under the brand ID.
  • Meta's own data (daily and hourly numbers, ads, campaigns, ad sets, activity log) stays filed under the Meta account it came from. A brand's Meta totals are the sum of its connected accounts, which fixes the multi-account brands.
  • One lookup, forever. Every old ID (act_…, asana_…) is kept as an alias that points to the new brand ID. Old Slack buttons, old links, the Asana webhooks, Supply, and the saved brand in each person's browser all keep working.
  • Discovery stops creating brands. Meta accounts we can see but haven't connected show up in Connections as "available to connect".
  • Missing connections are a normal state, not an error. Pages say "Connect Meta"; the Strategist knows what it can and can't see and says so.

How it ships

Five phases, each one live and checked before the next

Phase 1 · foundation

Brands, connections and aliases exist, filled from today's data

  • New tables: brands, connections, brand aliases. Backfill every active brand, its Meta account, Triple Whale shop, Slack channels, and the Google, TikTok, Klaviyo and Asana settings that already live in brand docs.
  • One function every route uses to turn any ID (old or new) into a brand.
  • Old tables are still the source of truth; the new ones are mirrored on every change.

Done when every active brand has a matching brand row and its connections, and counts line up.

Phase 2 · brands without Meta

The Slack router, the Strategist and the syncs read brands and connections

  • The Slack router asks "is this a brand's channel?" from brands, not ad accounts. Speedin goes live here: name plus #speedin-internal, and tags get answered.
  • Meta and Triple Whale syncs run per connection, not per brand. Brands with two ad accounts add up both.
  • The Strategist sees each brand's connections and answers honestly about what's missing.

Done when Speedin answers in Slack, every existing brand's numbers match the day before to the cent, and the nightly runs clean.

Phase 3 · the big move

Every brand-owned table and setting moves to the brand ID

  • Done overnight with the crons paused (about 30 minutes). A restore point is taken right before, so the database can be put back in one step.
  • Each table is copied across with a row-count check. Saved settings are renamed. Stored files keep their paths; the rows record the path instead of rebuilding it from the ID.
  • The temporary asana_… IDs and the code that moved new clients' data go away.

Done when every table's counts match before and after, and a full click-through of every tab for 3 brands shows the same thing as before.

Phase 4 · screens

The front end and every route speak brand IDs

  • The brand picker, the Overview, Paid ads, Brief, Reports, Studio, Season and the rest switch over. Old saved picks and old links resolve through the aliases.
  • "Connect Meta / Triple Whale / Google" states everywhere a connection is missing.
  • Supply's link to Locus brands switches to the brand ID.

Done when a brand with no connections and a brand with all of them both look right on every tab.

Phase 5 · adding brands

Add brand and Connections, rebuilt around the new model

  • Add brand = name + internal channel. It's live immediately. New client flow creates the brand on day one.
  • Connections page per brand: what's connected, sync health, and "available to connect" Meta accounts.
  • After two clean weeks, the old brand columns on the ad-account table are removed.

Done when a brand can go from nothing to fully connected without touching code or the database.

Safety

What protects the live system

  • A database restore point before every phase that changes data (D1 keeps 30 days of point-in-time restore).
  • Phases 1 and 2 only add things; nothing old is removed until phase 5.
  • Numbers are compared before and after for every brand: spend, revenue, ROAS, orders, brief and report counts.
  • Clients see nothing change. Briefs and reports go out the same way the whole time.

Biggest risk

Phase 3, if a cron writes under the old ID mid-move. That's why the crons are paused for it and the move runs as one step per table with counts checked, and why there's a restore point right before.
